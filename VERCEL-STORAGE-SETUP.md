# Подключение постоянного хранилища для mart-treid

## Что установлено при проверке

- Работа ведётся в `/workspaces/vigilant-octo-tribble`, репозиторий не менялся.
- Проект Vercel `mart-treid` существует. Доступный коннектор не предоставляет список подключённых баз и переменных окружения, поэтому наличие Neon в Vercel пока не подтверждено.
- В локальном окружении отсутствует `DATABASE_URL`.
- Отдельный случайный ключ `CONNECTIONS_ENCRYPTION_KEY` создан в `.env.local`. Значение не выводилось; файл исключён из Git и имеет права 600. Пароли и `AUTH_SECRET` не менялись.
- До добавления строки подключения миграция и проверка реального сохранения недоступны. Локальные черновики не заменяют PostgreSQL.

## Что нажать в Vercel

1. Откройте [проект mart-treid](https://vercel.com/anastas/mart-treid), затем **Storage**.
2. Если ресурс **Neon** уже есть, откройте его и проверьте, что в подключённых проектах указан **mart-treid**. Используйте существующую базу.
3. Если Neon нет, откройте [Neon в Marketplace](https://vercel.com/marketplace/neon), нажмите **Install**. Выберите команду **Anastas**, тариф, имя базы и регион. Проверьте условия выбранного тарифа перед созданием.
4. На шаге подключения ресурса выберите существующий проект **mart-treid** и необходимые окружения. Новый проект Vercel не создавайте.
5. Вернитесь в **mart-treid → Settings → Environment Variables**. Проверьте наличие переменной с точным именем **DATABASE_URL**. Если интеграция создала имя с префиксом, добавьте `DATABASE_URL` с тем же значением для нужного окружения. Не используйте префикс `NEXT_PUBLIC_`.
6. В этом же разделе нажмите **Add Environment Variable**. Имя: **CONNECTIONS_ENCRYPTION_KEY**. Значение: скопируйте непосредственно из уже созданной строки в открытом `.env.local`. Добавьте для окружений, использующих эту базу. Если ключ в Vercel уже существует и база содержит зашифрованные подключения, не заменяйте его: используйте прежний ключ локально.
7. Скопируйте значение **DATABASE_URL** непосредственно из защищённого интерфейса Vercel/Neon в `.env.local` текущего проекта. Ключи и строку подключения не отправляйте в чат, не сохраняйте в исходниках, скриншотах или отчётах. Остальные строки `.env.local` сохраните.
8. Не нажимайте **Redeploy**: публикация будет выполнена отдельно после проверки и вашего подтверждения. Переменные Vercel применяются к новым развёртываниям; для локальной проверки достаточно `.env.local` и перезапуска локального процесса.

Если названия экранов отличаются: путь через Marketplace → Neon → Install → подключение ресурса к существующему проекту описан в [официальной документации Vercel](https://vercel.com/docs/marketplace-storage). Настройки окружений — в [документации переменных](https://vercel.com/docs/environment-variables).

## Миграция и проверка после добавления DATABASE_URL

Из текущей рабочей папки:

```bash
npm run storage:check
npm run storage:migrate
npm run storage:verify
```

- `storage:check` читает настройки и проверяет схему; до миграции допустимо сообщение о необходимости миграции.
- `storage:migrate` применяет **migrations/001-connections.sql** одной транзакцией. Не запускается автоматически в HTTP-запросах, при сборке или публикации. Существующие таблицы не удаляет.
- `storage:verify` вызывает реальные обработчики API текущего приложения и реальную базу: создаёт отдельную служебную запись CRM без связей, проверяет чтение, редактирование, включение, выключение, конфликт версии, права user, шифрование и удаление. Внешний CRM API не вызывается. Проверочная запись удаляется; существующие записи не изменяются. Команда проверяет серверный путь API → PostgreSQL, а не браузерную отправку формы и не доступ к Google/Финтабло.

После миграции перезапустите локальный сервер, войдите как admin → **Источники данных → Проверить готовность системы**. Все три проверки должны показывать «Готово». До этого формы подключения источников скрыты. Затем вводите реальные реквизиты через панель, сохраняйте подключение и проверяйте доступ к источнику.

### Если нет доступа к локальному терминалу

Миграцию можно выполнить в Vercel: **mart-treid → Storage → ваша база → Browser → Query** (нужны права Owner), вставить содержимое `migrations/001-connections.sql` и выполнить запрос. Альтернатива: **Open in Neon → SQL Editor**. Для проверки реального сохранения всё равно потребуется запустить текущую версию приложения или `storage:verify` с её настройками. Публикация для миграции не требуется.

## Сообщения об ошибках

| Сообщение | Действие |
| --- | --- |
| Не настроен DATABASE_URL | Добавить строку подключения в окружение нужного процесса |
| Некорректный DATABASE_URL | Использовать PostgreSQL connection string из Neon |
| Не настроен/неверен ключ шифрования | Проверить 64 hex-символа и отдельный ключ, отличный от AUTH_SECRET |
| Схема подключений не готова | Выполнить storage:migrate |
| База отклонила авторизацию | Обновить строку подключения из Neon |
| Недостаточно прав | Проверить права роли базы на таблицы и миграцию |
| Не удалось связаться с базой | Проверить Neon, сеть и актуальность строки подключения |

Сырые ошибки драйвера, пароли и connection string не выводятся в сообщения API и диагностических команд. Сохранённые реквизиты источников не возвращаются в браузер; вводимые реквизиты передаются только в теле запроса и очищаются после операции. На опубликованном сайте передача выполняется по HTTPS.
