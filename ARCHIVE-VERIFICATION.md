# Дашборд по PDF и постоянный архив

Проверено 28.09.2026. Визуально изучены все четыре страницы добавленного PDF «референс дашборды новый.pdf». Растровые страницы сохранены в `artifacts/reference/page-1.png` … `page-4.png`.

## Интерфейс

Зелёная общая верхняя панель, серо-мятный фон, белые карточки, компактные фильтры рядом с заголовком, выбор группы разделов и отдельное подменю воспроизводят композицию PDF. Цвет верхней панели взят из референса: `#1f8e63`. На экране остатков — общий баланс, раскрываемые счета и две колонки остатков/резервов; на экране денег — четыре показателя, кольцевая диаграмма выплат и график потоков; на экране ДЗ — показатели, сравнение, таблицы по источникам и крупнейшим должникам. Детализация, поиск, выгрузка и дополнительные существующие экраны сохранены. Мобильная навигация открывается отдельной панелью.

ДЗ находится в «Оперативных», как на странице 3 и в задании. На странице 4 PDF её положение противоречит этому — такое перемещение не переносилось. Числа, названия компаний, пути к файлам и формулы резервирования из PDF не используются. Вместо неподтверждённых резервов, планов и исторических остатков показаны пустые состояния. Сохраняются существующие группировки ДЗ и фактические поступления/выплаты; отсутствующие в источниках разрезы не придуманы. Это соответствие композиции при реальных данных, а не буквальная копия содержимого PDF.

Источники, учётные данные, исходные файлы, правила импорта и формулы не изменены. Настройки остаются в административном меню с прежними проверками прав. Новые представления сохраняют привязку разрешений: поступления/выплаты и проекты — `cash`, зарплата — `overview`, план — `opiu`. Отдельного действующего модуля планирования в исходном проекте не было; экран не подставляет фиктивный план.

## Хранение и сохранность

Архив хранится **в существующем внешнем PostgreSQL (Neon), таблица `mart_dashboard_archive`**, а не в памяти процесса, браузере или файловой системе сервера. Таблица содержит зашифрованный полный ответ, период, дату создания, дату наблюдения источников, дату проверки содержимого, версию схемы, версию расчётов, отпечатки конфигурации и исходных данных, ошибки и аренду фонового задания. В `mart_source_snapshots.content_hash` записывается стабильный отпечаток содержимого синхронизации; одно лишь новое время синхронизации не инвалидирует историю.

Применены добавочные миграции `004-dashboard-archive.sql` и `005-durable-period-archive.sql`. Для другого окружения: `npm run archive:migrate`. Действующие данные не удаляются. Версия структуры — 2; версия расчётов задаётся `CALCULATION_VERSION` в `app/lib/archive-version.ts` и должна повышаться при изменении расчётной логики.

**После перезапуска и повторного развёртывания нужно сохранять прежние `DATABASE_URL` и `CONNECTIONS_ENCRYPTION_KEY`.** Новый процесс читает ту же внешнюю таблицу; build и deploy её не очищают. Ключ используется для AES-256-GCM и проверки целостности. Замена базы либо утрата ключа не сохраняет доступ к прежним снимкам. Эти настройки в ходе работы не изменялись. Проверен запуск чтения в отдельном Node-процессе с запрещённым чтением источников. Фактическое повторное развёртывание в Vercel не выполнялось; сохранность при нём обеспечивается внешней БД и сохранением этих настроек.

Снимок дашборда содержит выбранный диапазон, данные сравнения, строки для таблиц/графиков/детализации, ДЗ и секционные показатели. ОПиУ сохраняется целиком со всеми доступными месяцами и направлениями; фильтрация использует прежние функции. Перед выдачей применяется действующая проверка секционных прав. Текущие остатки и дата расчёта ДЗ сохраняют исходную семантику и не выдаются за исторические остатки выбранного периода.

Публикация полного снимка атомарна, после успешной обработки. Аренда задания в PostgreSQL на 4 минуты и уникальный токен защищают от параллельной записи и позднего завершения старого процесса. Неполная обработка не заменяет исправный payload. Отсутствующий, повреждённый или несовместимый снимок приводит к обычной загрузке и последующему сохранению. Недоступное хранилище не блокирует обычный способ загрузки.

## Актуальность без пятиминутного пересоздания

- **У исторических периодов нет TTL.** Возраст снимка сам по себе не вызывает пересоздание. Пять минут оставлены только для диапазонов, включающих сегодняшний или будущий день.
- Изменение версии расчётов, конфигурации подключения или содержимого пересекающегося исходного снимка инвалидирует соответствующий архив при обращении.
- Для Google Sheets добавлена проверка версии файла через метаданные Drive API с существующей служебной учётной записью, без чтения ячеек. Изменение версии до/после чтения защищает от публикации данных, изменявшихся во время обработки.
- **В проверенной среде метаданные Drive API недоступны.** Подключения Sheets при этом работают. Интерфейс явно сообщает, что версия не подтверждена; это не маскируется статусом «актуально».
- Для проверки внешних исправлений используется фоновое чтение при обращении к историческому архиву, не чаще одного раза в час. Это проверка по обращению, не отдельный круглосуточный планировщик. При отсутствии обращений автоматический опрос не идёт. До завершения проверки пользователь получает сохранённый снимок с датой данных и сообщением о границе актуальности. Для немедленной проверки доступно ручное обновление.
- Если содержимое не изменилось, фоновая проверка обновляет только метаданные: **зашифрованный payload и дата создания остаются прежними**. Изменённые факты публикуются новым снимком. Сравнение игнорирует время опроса, но учитывает значения и вложенную историческую детализацию ДЗ.

## Использование

Обычное открытие периода автоматически использует подходящий архив. Дата данных показывается на странице; сообщение о проверке доступно рядом в «Проверка актуальности».

Администратору: **Администрирование → Источники и архив → Архив периодов**. Выберите период дашборда либо ОПиУ и нажмите «Создать/обновить архив», либо «Обновить» в строке списка. Запрос возвращает 202; обработка через Next.js `after` не блокирует интерфейс. Статус опрашивается каждые 4 секунды. В списке видны даты создания/чтения/проверки, версии, ошибки и прерванные задания.
