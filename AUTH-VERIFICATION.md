# Проверка POST-входа — 15 сентября 2026

## Повторная проверка 18 сентября 2026

Продолжена работа над входом через адрес GitHub Codespaces. `app/lib/request-origin.ts` определяет допустимый внешний Origin по серверному окружению; подставленные `X-Forwarded-*`, чужой workspace и другой порт не дают разрешения на запрос. Общая проверка применяется к входу и защищённым изменяющим API. Обычная HTML-форма возвращает 303 на разрешённый внешний адрес. Временный вывод `ORIGIN_DIAGNOSTIC` из `proxy.ts` удалён.

Проверки завершены успешно:

- 45 серверных тестов: 22 основных, 15 по дебиторке и 8 сравнительных с Apps Script.
- ESLint, TypeScript, `git diff --check` и production-сборка `npm run build` (Turbopack).
- Отдельный браузерный прогон production-сборки: user/admin, правильный и неправильный пароль, включённый и отключённый JavaScript, доступ по роли, HttpOnly-cookie и выход. Страница входа проверена на 320/375/390/430/768/1440 px, скриншот просмотрен. Реквизиты не обнаружены в URL запросов и логах тестового сервера.

В тест добавлен `MART_TEST_AUTH_ONLY=1`; результат: `artifacts/verification/auth-focused-report.json`. При проверке режима JavaScript тест теперь явно ждёт подключения React-обработчика формы: одного `networkidle` в dev-режиме оказалось недостаточно, и форма успевала перейти в штатный сценарий без JavaScript.

Границы: браузерный прогон выполнен локально с временными учётными данными, а внешний Origin Codespaces проверен серверными тестами. Полный вход через публичный прокси GitHub в этой проверке не выполнялся. Меню, источники и расчёты не перепроверялись в браузере. `.env.local` и опубликованный сайт не менялись. Ниже сохранён первоначальный отчёт.

## Результат

Исправлена отправка логина и пароля через URL. Публикация и развёртывание не выполнялись.

Причина: обработчик JavaScript уже использовал POST, но у HTML-формы отсутствовали `method` и `action`. До загрузки JavaScript или при его блокировке браузер мог отправить поля методом GET в адрес страницы.

## Изменения

- `app/login/login-form.tsx`: явные `method="post"` и `action="/api/auth/login"`. При работающем JavaScript учётные данные по-прежнему передаются в JSON-теле POST.
- `app/api/auth/login/route.ts`: поддержка обычной POST-формы (`application/x-www-form-urlencoded`). После успеха — 303 на `/`, после ошибки — 303 на `/login?error=auth`. В адресах, ответах и сообщениях нет введённых логина и пароля. Параметры URL отклоняются; проверка Origin и ограничение попыток сохранены.
- `app/login/page.tsx`: фиксированное сообщение об ошибке для входа без JavaScript; значения параметров не выводятся как текст ошибки.
- `next.config.ts`: `Cache-Control: private, no-store` и `Referrer-Policy: strict-origin` для страницы входа и API авторизации. Referer не передаёт путь и параметры; Origin сохраняется для проверки обычной формы.
- `tests/core.test.cjs`: проверки JSON и HTML-формы для обеих ролей, ошибок, недопустимого Origin, формата запроса и параметров URL.
- `tests/auth-browser-check.mjs`: воспроизводимая локальная проверка через agent-browser. Временные пароли со специальными символами создаются в памяти; текущий `.env.local` не меняется. В отчёт не записываются тела запросов, cookies и учётные данные.
