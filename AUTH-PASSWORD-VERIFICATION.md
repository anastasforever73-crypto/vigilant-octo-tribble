# Авторизация: ровно 4 символа — 15 сентября 2026

## Что изменено

- Для `user` и `admin` разрешён пароль **только из 4 символов Unicode** (кодовых точек). Одно правило используется формой, сервером, `setup-auth` и `hash-password`. Пароли из 3 и 5 символов отклоняются; более длинные прежние пароли больше не принимаются.
- Передача учётных данных остаётся только через POST: JSON при работающем JavaScript и обычная HTML-форма при его отсутствии. GET API входа возвращает 405, параметры URL не принимаются. В ответах, перенаправлениях и логах приложения пароль не выводится.
- Сохранён scrypt: N=32768, r=8, p=3, случайная соль 16 байт, ключ 64 байта. Сравнение хешей выполняется через `timingSafeEqual`.
- После пятой неудачной проверки учётная запись блокируется на 15 минут, отсчитываемых от пятой ошибки. Правильный пароль во время блокировки также отклоняется. Успешный вход обнуляет счётчик. Параллельные проверки одной роли выполняются последовательно, чтобы не обойти порог. JSON API возвращает 429 и Retry-After; обычная форма перенаправляется на безопасную страницу ошибки без сессии.
- При неверном логине и неверном пароле возвращается одинаковое сообщение. Проверка Origin сохранена.
- Cookie всегда имеет `HttpOnly`, `Secure`, `SameSite=Strict`, в том числе при локальной разработке.

## Сброс паролей

```bash
npm run setup-auth -- --reset
```

Команда запрашивает два новых пароля скрыто, с подтверждением. Логины сохраняются. Меняются хеши паролей и AUTH_SECRET, поэтому прежние сессии отзываются. Остальные настройки `.env.local` сохраняются побайтово, включая многострочные ключи источников. Запись атомарная, права файла — 600; сохранены проверки Git, типа файла и конкурентных изменений. Отмена сброса не изменяет `.env.local`. Без `--reset` перезапись существующей авторизации запрещена.

Сброс проверен во временных Git-проектах именно через npm. Текущий `.env.local` не изменялся; фактические пароли проекта не сбрасывались. Чтобы заменить прежние пароли другой длины, владельцу нужно выполнить указанную команду и перезапустить локальный сервер.

## Ограничение блокировки

Счётчики и очередь находятся в памяти одного серверного процесса. Перезапуск очищает их; разные экземпляры сервера не разделяют блокировку. До публикации для нескольких экземпляров нужен общий постоянный механизм ограничения попыток. Это ограничение указано также в README; распределённая защита в данном изменении не внедрялась.

Проект не опубликован. Внешние настройки источников и развёртывания не изменялись.
