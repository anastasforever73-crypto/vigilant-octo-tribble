# Timeweb: очищенная демонстрационная версия

Ветка: restore/timeweb-demo-clean. Это независимая история с одним корневым
коммитом, без предков исходного репозитория. Main не изменяется.
Клиентский mart-data.json исключён: используется синтетический demo-data.json.
Все операции, названия и суммы набора вымышлены; интерфейс помечен ДЕМО.
Страница проверяет сессию до передачи данных, JSON не импортируется значением
в клиентский компонент. После входа пользователь получает демонстрационные
данные для расчётов интерфейса; авторизация не скрывает их от вошедшего пользователя.

Репозиторий: anastasforever73-crypto/vigilant-octo-tribble
Ветка: restore/timeweb-demo-clean

Публикация данной ветки не изменяет main или её автодеплой.

## Обязательные переменные авторизации

AUTH_SECRET — случайный секрет минимум 32 символа.
USER_LOGIN, USER_PASSWORD_HASH — логин и scrypt-хеш обычного пользователя.
ADMIN_LOGIN, ADMIN_PASSWORD_HASH — другой логин и scrypt-хеш администратора.
Нужны обе пары. Открытые пароли не помещаются в переменные и репозиторий.

В доверенной Git-копии выполните npm run setup-auth. Скрипт создаёт .env.local
с правами 600, исключённый из Git, со скрытым вводом паролей. Он генерирует
48 случайных байт для секрета и индивидуальные соли для scrypt.
Перенесите значения в окружение Timeweb, не загружая файл в Git.
Хеши в панели вводятся с обычными $, без кавычек и dotenv-экранирования.
Фактическая восстановленная политика — ровно четыре Unicode-символа.
Сессия подписана, cookie HttpOnly/Secure/SameSite=Strict.
Лимит ошибок входа хранится в памяти процесса и не общий для нескольких серверов.

## Реальные данные не подключены

Маршрут /api/google-sheets требует администратора, но возвращает 503 с явным
сообщением о демонстрационном режиме. Сохранённый код Google-чтения не вызывается.
Не задавайте реквизиты реальных источников для этого первого запуска.
Neon и Vercel API этой ранней версии не нужны. Современные Excel, архивы и
персональный реестр пользователей не входили в раннюю исходную версию.

Для будущего подключения данных нужна отдельная проверенная правка: серверный
адаптер должен преобразовывать данные защищённого источника в существующую схему,
проверять авторизацию и права, валидировать ответы и исключать секреты из ошибок.
Ключи остаются в серверном окружении. GOOGLE_SERVICE_ACCOUNT_EMAIL,
GOOGLE_PRIVATE_KEY и GOOGLE_SHEET_ID нужны сохранённой Google-реализации;
GOOGLE_SHEET_RANGES необязательна. Само заполнение переменных не включает чтение.
Для Google нужен сервисный аккаунт с доступом Читатель и включённым Sheets API.
Возвращать клиентский JSON-снимок в Git, public или клиентский импорт нельзя.

## Проверки

npm ci, production-сборка и HTTP-проверки запуска/авторизации выполняются
на синтетических реквизитах, без реальных источников. Подтверждение локальной
сборки не заменяет проверку выбранного Linux-окружения Timeweb после деплоя.
