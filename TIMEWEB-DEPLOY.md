## Сохранение доступа и данных

Не запускайте `setup-auth` при переносе действующего приложения. Оставьте
пять существующих переменных Timeweb: `AUTH_SECRET`, `ADMIN_LOGIN`,
`ADMIN_PASSWORD_HASH`, `USER_LOGIN`, `USER_PASSWORD_HASH`.
Совместимость сохранённых сессий и прежних четырёхсимвольных паролей
ограничена исходными настроенными аккаунтами. Управляемый реестр и его
отключения имеют приоритет; новые аккаунты сохраняют политику Vercel.

Текущий план — отдельная PostgreSQL Timeweb в Москве MSK-1. Транспорт
переведён с Neon HTTP на стандартный TCP-драйвер `pg`; подробная инструкция
создания базы, TLS и приватной сети находится в `TIMEWEB-POSTGRES-RU.md`.
Не подключайте новый ключ к старой базе Neon. Исходный ключ не найден:
доступные настройки и пользователей переносим из защищённой резервной копии
в новую пустую базу по `TIMEWEB-RECOVERY.md`. Читаемость прежних зашифрованных
архивов не подтверждена; они сохранены в отдельной резервной копии.

Перед выпуском проверьте TLS командой `storage:tls-check`, выполните
восстановление на новой базе, затем `migration:check` с её защищённой
конфигурацией. Скрипт preflight делает только SELECT: проверяет схему,
реестр, конфликты логинов и расшифрование уже новых подключений. Реестр
переносится целиком; одного DASHBOARD_USERS_JSON вместо него недостаточно.
Не запускайте миграции/восстановление против действующей базы Vercel/Neon.

Укажите `APP_ORIGIN` равным точному публичному HTTPS origin Timeweb без
завершающего слеша. Прокси должен сохранять Host. Произвольные forwarded
заголовки не расширяют список доверенных адресов. Если APP_ORIGIN пока не задан,
production-сервер за loopback-прокси принимает только HTTPS Origin, точно
совпадающий с реальным Host запроса; localhost и режим разработки не
получают это исключение. Явный APP_ORIGIN сохраняет строгий приоритет.

## Сборка и проверка

Используется сервер Next.js, не статический экспорт. Сохраняются
`npm run build`, `npm start`, порт из `PORT`. Сборка использует проверенный
webpack; добавлен маркер `/build-info.json` с Git SHA (если checkout доступен
в build-контейнере) и SHA-256 кода. Маркер не содержит секретов.

Проверки: `npm test`, `npm run test:archive`, `npm run test:excel`,
`npm run test:timeweb`, `npm run lint`, `npm run build`.
Локальные проверки выполняются с временными аккаунтами. Отсутствие реальной
базы в изолированной проверке не подтверждает работу production-источников:
их нужно проверить после переноса серверных настроек.

## Выпуск и откат

До обновления подключённой ветки сохраните её исходный SHA в отдельной
ветке `rollback/timeweb-before-vercel-20261110` и локальном git bundle.
Обновляйте `restore/timeweb-demo-clean` обычным fast-forward push без force.
В Timeweb подтвердите успешный деплой ожидаемого SHA, сравните
`/build-info.json` с локальной сборкой и проверьте вход, роли, источники,
архивы и Excel. Сохраните предыдущий успешный деплой Timeweb.
При проблеме выберите предыдущий коммит в настройках/истории деплоя Timeweb;
не меняйте и не удаляйте production-базу, реестр и ключ шифрования.
