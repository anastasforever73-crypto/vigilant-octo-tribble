# Локальная резервная копия

В панели администратора откройте «Источники» → «Резервные копии». Укажите отдельный пароль длиной от 12 символов, повторите его и нажмите «Скачать резервную копию». Проверьте файл .martbackup в загрузках. Храните пароль отдельно: восстановить его невозможно.

Копия содержит пользователей и их права/хеши паролей, подключения и ключи источников, историю ставок кошелька, сохранённые снимки, отчёты и архивы входных данных. Это логическая копия состояния приложения, а не полный дамп PostgreSQL. Действующие сессии, корневые учётные данные администратора и серверные ключи приложения не экспортируются. Данные защищены scrypt + AES-256-GCM; поддерживаемый размер исходных данных до 64 МиБ.

Для восстановления выберите файл, введите пароль и нажмите «Предварительный просмотр копии». Проверьте состав и дату, затем подтвердите замену. Изменение текущих данных после просмотра требует повторного просмотра. Ошибка при записи откатывает замену целиком. Серверный администратор сохраняет доступ; пользователи входят заново.

## Временное хранение без внешней базы

На одном экземпляре Node.js установите TEMPORARY_STORAGE_ENABLED=true без DATABASE_URL. В памяти процесса запускается PGlite с текущими миграциями. Пользователи, источники и ставки редактируются через настоящие API приложения. Память общая для пользователей одного процесса, но не для нескольких экземпляров приложения. Перезапуск, сбой или публикация обновления удаляют данные: заранее скачайте копию, после запуска восстановите вручную. Сведения о последней выдаче копии также исчезают после перезапуска. Браузер сам выбирает место сохранения; приложение не подтверждает наличие файла на диске.

DATABASE_URL имеет приоритет. При последующем переносе в PostgreSQL сначала примените миграции и настройте CONNECTIONS_ENCRYPTION_KEY. Настройки источников из переменных окружения должны совпадать с копией; если они различаются, предварительный просмотр блокирует восстановление до их переноса в настройки хостинга. Временный режим восстанавливает эти настройки в памяти. Существующий серверный администратор и AUTH_SECRET остаются заданными на хостинге.

## Проверка

npm test включает тест шифрования и сквозной тест временного хранилища с восстановлением после сброса памяти. Дополнительно проверен собранный Next.js через HTTP: создание пользователя и источника, ограничения доступа, скачивание, перезапуск процесса, восстановление, вход пользователя и отзыв доступа.
