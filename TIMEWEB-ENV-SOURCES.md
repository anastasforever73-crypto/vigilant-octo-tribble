# Источники без PostgreSQL

Приложение остаётся в Timeweb App Platform. Источники читаются напрямую;
DATABASE_URL для этого режима не задаётся. Секреты хранятся только в закрытых
переменных приложения, не в репозитории или браузере.

Настройки Google: GOOGLE_SERVICE_ACCOUNT_EMAIL, GOOGLE_PRIVATE_KEY,
GOOGLE_SHEET_ID, DEBT_GOOGLE_SHEET_ID; GOOGLE_SHEETS_ENABLED=true,
DEBT_ENABLED=true. Поддерживаются настоящий многострочный ключ и литералы \n.
Сопоставление дебиторки восстановлено из сохранённой конфигурации:
DEBT_TRANSIT_SHEET=Заказы, DEBT_STOCK_SHEET=Склад.
Лист остатков основной таблицы: ACCOUNT_SHEET=техн р\с остатки
(один буквальный обратный слеш).

Финтабло требует FINTABLO_API_TOKEN и FINTABLO_API_URL. До получения
действующего токена FINTABLO_ENABLED=false. Сохранённый старый токен зашифрован
утраченным ключом и не выдаётся за рабочий. Счета и плановые привязки
из старой базы автоматически через переменные не восстанавливаются.

Обработка основной таблицы использует только операции выбранного периода
и периода сравнения. Некорректные суммы вне периода не блокируют его;
внутри периода суммы по-прежнему проверяются строго. Необязательный текст
в дате доставки означает отсутствие даты, не меняя суммы заказа.
Для истории кредиторки НЛПК используется существующий проверенный разбор
A6/G, включая последнюю физическую строку на одинаковую дату.

Без базы нет постоянных архивов, редактирования подключений через панель,
сохранения общей ставки кошелька и управляемого реестра пользователей.
Источники настраиваются через серверные переменные с повторным деплоем.
Текущие AUTH_SECRET и четыре переменные входа сохраняются без изменения.

Позже: восстановить отдельную PostgreSQL по TIMEWEB-RECOVERY.md, настроить
DATABASE_URL и соответствующий ключ, проверить миграции, реквизиты и связи.
После сверки сохранённых подключений убрать заменённые временные переменные
источников, чтобы их приоритет не мешал настройкам базы. Базу не создавать
автоматически при чтении дашборда.
