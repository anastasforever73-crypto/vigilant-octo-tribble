# Передача проекта разработчику

Архив содержит текущее состояние рабочего каталога на 18.09.2026, включая изменённые и новые незакоммиченные файлы. Это не экспорт последнего коммита. Секреты, клиентские выгрузки, результаты проверок, зависимости и сборки не передаются. Приложение не опубликовано в рамках передачи.

## Установка и запуск

Нужны Node.js 20.9+ (рекомендуется Node.js 22 LTS), npm и Git. Команды выполняются в распакованном корне проекта.

```bash
npm ci
git init
cp .env.example .env.local
npm run setup-auth
npm run dev
```

`git init` нужен, поскольку каталог `.git` исключён, а `setup-auth` проверяет, что `.env.local` не отслеживается Git. Настройку запускать в интерактивном терминале: она запросит два разных логина и пароли, создаст секрет сессий и scrypt-хеши, не показывая пароли. Текущая политика требует ровно четыре символа Unicode. Настройки в `.env.local` заполняются реквизитами, переданными владельцем отдельно. Для работы приложения не нужны исключённые JSON-снимки данных.

Адрес разработки: http://localhost:3000, ОПиУ: http://localhost:3000/?tab=opiu. Без реквизитов источники показывают недоступность, а не демонстрационные данные. После изменения окружения перезапустить сервер.

```bash
npm run build
npm start
```

Для Codespaces: `npm run start:codespaces` после сборки, приватный порт 3100. При другом порте одновременно задавать `PORT` и порт запуска: `PORT=3101 npm start -- --port 3101`. Для удалённого использования нужен HTTPS: сессионная cookie имеет Secure. Не менять защиту cookie ради обхода настройки сервера.

## Окружение

В передаваемом `.env.example` все значения пустые. Секреты только серверные, без префикса `NEXT_PUBLIC_`.

| Переменные | Назначение |
| --- | --- |
| `AUTH_SECRET` | Секрет подписи сессий, минимум 32 символа; создаётся setup-auth |
| `USER_LOGIN`, `USER_PASSWORD_HASH`, `ADMIN_LOGIN`, `ADMIN_PASSWORD_HASH` | Две роли и scrypt-хеши; создаются setup-auth |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY` | Серверный сервисный аккаунт Google, доступ к нужным таблицам «Читатель»; включить Google Sheets API |
| `GOOGLE_SHEET_ID` | Основная таблица ДДС, продаж и остатков |
| `DEBT_GOOGLE_SHEET_ID` | Отдельная таблица дебиторки; не подменяется основной таблицей |
| `DEBT_TRANSIT_SHEET`, `DEBT_STOCK_SHEET` | Физические вкладки дебиторки; по умолчанию «Транзит» и «Склад» |
| `CASH_SHEET`, `ORDERS_SHEET`, `DEBTOR_SHEET`, `FACTORY_SHEET`, `WALLET_SHEET`, `ACCOUNT_SHEET` | Имена вкладок основного адаптера; значения по умолчанию в app/lib/source-settings.ts |
| `DEBT_SHEET` | Совместимая прежняя настройка; современная дебиторка использует две отдельные вкладки |
| `GOOGLE_SHEET_RANGES` | Необязательный JSON-массив диапазонов для /api/google-sheets; не перенастраивает основной адаптер |
| `GOOGLE_SHEETS_ENABLED`, `FINTABLO_ENABLED`, `DEBT_ENABLED` | Отключение соответствующих источников значением false; пустое значение означает включение. Отдельный /api/opiu этим флагом Google не отключается |
| `FINTABLO_API_URL` или `FINTABLO_API_BASE_URL`, `FINTABLO_API_TOKEN` | API Финтабло; первый URL имеет приоритет |
| `DATABASE_URL` | Необязательный для базовых источников Neon PostgreSQL; нужен для сохранённых подключений |
| `CONNECTIONS_ENCRYPTION_KEY` | Отдельный ключ AES-256-GCM: 32 случайных байта в 64 hex-символах, не AUTH_SECRET |
| `PORT` | Порт сервера, также используется проверкой Origin |
| `CODESPACES`, `CODESPACE_NAME`, `GITHUB_CODESPACES_PORT_FORWARDING_DOMAIN` | Предоставляются средой Codespaces; нужны для доверенного внешнего адреса |

Google private key поддерживает многострочную запись и экранированные переводы строк. Не включать JSON-ключ сервисного аккаунта в репозиторий. При ручном сохранении scrypt-хеша в `.env.local` экранировать `$` как `\$`; setup-auth делает это автоматически. Реквизиты прежнего окружения и содержимое базы в архив не включены.

## Источники и правила

- **ОПиУ:** только «Анализ ОПИУ», точное имя в Google Sheets — `Анализ ОПИУ ` с пробелом в конце. Workbook ID задан в `app/lib/opiu.ts` как `OPIU_WORKBOOK`; это идентификатор источника, не ключ доступа. Чтение реализовано в `app/lib/read-opiu.ts`, API — `/api/opiu`. Отдельные месячные вкладки и квартальные столбцы не используются.
- **Сентябрь 2026 исключён только из ОПиУ**, включая выбор, итоги, графики и сравнения. Это не глобальный фильтр: дебиторка, ДДС, продажи и другие разделы сохраняют свои периоды. Сейчас для ОПиУ доступны апрель–август 2026, по умолчанию август.
- ОПиУ сохраняет порядок и значения строк блоков «ИТОГО», «ТРАНЗИТ», «СКЛАД». Итоговые строки не складываются с детализацией, «ИТОГО» не пересчитывается из других блоков. Диапазон суммирует одну статью по месяцам; ошибки и пропуски не становятся нулями, проценты не суммируются. План не придуман. График появляется только для двух и более месяцев. Номера статей удаляются только из подписей, компактные суммы имеют точную подсказку.
- **Дебиторка:** «Транзит» и «Склад», текущий остаток по Москве; история только из подтверждённых снимков «Архив ДЗ». Учитываются частичные ошибки источников. Настройка может читаться из окружения или одного однозначного сохранённого подключения. Исключение сентября к ней не применяется.
- **ДДС, продажи, остатки:** основная Google-таблица по существующим сопоставлениям в `app/lib/google-dashboard.ts`; Финтабло через существующий адаптер. ДДС выбирается из одного источника, а не суммируется между поставщиками.
- **Сохранённые подключения:** административная панель и PostgreSQL, секреты и снимки зашифрованы. Сами записи и реквизиты необходимо получить отдельно. Наличие адаптера не подтверждает доступность конкретного API у получателя архива.

## База и скрипты

При необходимости постоянного хранения сначала настроить отдельную базу и ключ шифрования, затем выполнить `npm run storage:migrate` и `npm run storage:check`. Миграция: `migrations/001-connections.sql`. `storage:verify` создаёт и удаляет служебную запись: запускать осознанно на нужной базе. Без базы сохранение подключений недоступно, базовое чтение настроенных источников остаётся отдельным путём.

`scripts/Otchet_DZ.gs` — исходный Google Apps Script отчёта дебиторки. Он может изменять листы отчёта/архива, не запускается приложением автоматически. Не устанавливать и не выполнять в исходной таблице без отдельной задачи. Скрипты сравнения в scripts читают источники и создают локальные отчёты; они не нужны для обычного запуска.

## Проверки

```bash
npm test
npm run lint
npm run build
```

Модульные проверки ОПиУ включены в npm test. Для браузерных проверок отдельно требуется установленный agent-browser и браузер. Перед живыми проверками создать выходной каталог: `mkdir -p artifacts/verification`. Каталог исключён из передачи вместе с прежними данными и скриншотами.

```bash
OPIU_TEST_URL=http://127.0.0.1:3100 AGENT_BROWSER_BIN=/path/to/agent-browser node tests/opiu-live-browser-check.cjs
```

Живая проверка требует настроенной авторизации, доступа к Google Sheets и запущенного сервера. Она читает выбранную вкладку, сверяет API, проверяет месяц/диапазон, адаптивность и ошибки. Тестовые изменения ответов выполняются в браузере, исходная таблица не редактируется. Некоторые прочие браузерные сценарии используют фиксированные порты: сверить заголовок соответствующего теста. Итоги прежних проверок не являются гарантией доступа в новом окружении.

## Ограничения и следующие задачи

- Схема ОПиУ привязана к строкам заголовков и ключевым статьям текущей вкладки. При структурных изменениях нужен пересмотр адаптера; диапазон чтения ограничен 50 000 ячеек. Workbook ID пока задан в коде, отдельной настройки ОПиУ в административной панели нет.
- Обновление ОПиУ выполняется при открытии и по кнопке; расписания автообновления нет. Ошибки исходных формул сохраняются. Плановые показатели и проценты за диапазон требуют отдельных согласованных определений.
- Товар, логистика и CRM требуют подтверждённых схем и адаптеров; заглушки не являются подключёнными данными. Полный бухгалтерский баланс не выводится из денежных остатков.
- Историю дебиторки нельзя восстановить без настоящего архива. Финтабло не превращает текущие остатки в исторические.
- Четырёхсимвольные пароли — действующее ограничение проекта; для расширения эксплуатации требуется отдельное решение о политике доступа. Индивидуальный отзыв сессий и распределённое ограничение попыток входа требуют дальнейшей проработки.
- Смена ключа шифрования базы требует перешифрования сохранённых данных. Миграции, доступы источников и production-развёртывание должны быть проверены разработчиком в целевом окружении.
- README содержит историю реализации и ссылки на исключённые отчёты; актуальное состояние ОПиУ описано здесь и в OPIU-IMPLEMENTATION.md.

## Состав и исключения

Передаются app, public, scripts, tests, migrations, package.json, package-lock.json, конфигурации Next.js/TypeScript/ESLint/PostCSS, proxy.ts, совместимый route.ts и безопасные инструкции. Все исходники берутся с диска независимо от Git-статуса; удалённые файлы старого коммита не восстанавливаются.

Исключены `.env*` кроме очищенного `.env.example`, ключи и токены, `.git`, `.vercel`, node_modules, .next, кэши, логи, tsbuildinfo, предыдущие архивы, archive, artifacts, оба mart-data.json. Отчёты `*VERIFICATION.md`, `*REPORT.md`, `*PARITY.md`, `OPIU-SOURCE-AUDIT.md` и `RECEIVABLES-IMPLEMENTATION.md` исключены как материалы предыдущих проверок, содержащие либо способные содержать выгруженные клиентские показатели. Исходные файлы проекта не удалены.

`HANDOFF-MANIFEST.json` внутри ZIP содержит список переданных файлов, их SHA-256 и перечень исключённых материалов без содержимого. Проверка архива включает запрещённые пути, сигнатуры ключей/токенов и сравнение с секретными значениями локального окружения без вывода значений. Эта проверка не заменяет будущий контроль новых изменений.
