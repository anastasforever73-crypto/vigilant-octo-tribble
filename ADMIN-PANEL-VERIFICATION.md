# Админская панель после однократной настройки хранилища

## Реализовано

- Инфраструктура отделена от источников: серверные `DATABASE_URL` и `CONNECTIONS_ENCRYPTION_KEY`, затем одна миграция. Для каждого источника новые переменные Vercel не нужны.
- При отсутствии готового хранилища вместо редактора показано «Требуется первоначальная настройка хранилища». Кнопки добавления и формы не отображаются.
- Отдельный защищённый API `GET /api/connections/readiness` проверяет подключение к БД, наличие всех используемых столбцов четырёх таблиц миграции и формат/наличие отдельного ключа. Каждый пункт имеет независимый статус; недоступные проверки не выдаются за успешные.
- После готовности доступны существующие операции панели: добавить Google Sheets, задолженность, Финтабло, конфигурацию CRM; сохранить, редактировать, проверить, сопоставить, включить/отключить, удалить и вручную синхронизировать. Карточки показывают статус и время последнего успеха.
- Обновление реквизитов переведено с PATCH на POST `/api/connections/[id]`. Создание и проверка также POST. PATCH принимает только переключение состояния без секретов; секретные поля в других методах отклоняются.
- API возвращает фиксированные маски `••••••••` для сохранённых полей. Они не содержат реальных символов и не раскрывают длину. Поля ввода остаются пустыми; маска не подставляется как новый секрет и отклоняется при попытке сохранить её.
- Сохранено серверное шифрование AES-256-GCM. Пустые секретные поля оставляют старые значения; новый ввод заменяет их. Поля очищаются после операции.
- CRM с неизвестным API по просьбе пользователя пока пропущена. Хранение конфигурации подготовлено; реальная проверка, воронки, менеджеры и сделки потребуют документации и адаптера.

## Проверки

- Серверные тесты: **19/19 успешно** — включая контроль роли, Origin, шифрование, маски, POST-only для реквизитов, запрет секретов в URL и независимые статусы готовности.
- ESLint и TypeScript: успешно.
- Production-сборка: успешно. В 12 файлах клиентского пакета не обнаружены значения локальных серверных секретов.
- Браузерная проверка production-сборки: **22 проверки успешно**. Проверены роли, меню и адаптивность, экран первоначальной настройки, три результата готовности, повторная проверка и отсутствие неработающего редактора. Тестовый процесс изолирован от реальных источников и базы. Итог: `artifacts/verification/auth-post-report.json`; снимок: `artifacts/verification/admin-connections.png`.

## Граница готовности

`DATABASE_URL` по-прежнему отсутствует локально; `CONNECTIONS_ENCRYPTION_KEY` задан. `npm run storage:check` останавливается на отсутствующей строке подключения. Миграция к реальной базе не применялась.

**Полный успешный сценарий через панель с сохранением в PostgreSQL и получением реальных данных источника не выполнен.** Для этого требуются база и реквизиты источника, которые владелец введёт через готовую панель. Модульные проверки и экран первоначальной настройки не подменяют эту проверку.

Инструкция и три первоначальных действия: [ADMIN-SETUP.md](ADMIN-SETUP.md).

Точная команда миграции из корня текущего проекта после настройки окружения:

```bash
npm run storage:migrate
```

Серверный CRUD после миграции проверяется командой `npm run storage:verify`; браузерный успешный сценарий проверяется отдельно с реальным источником. Проект не публиковался.
