## Повторная настройка источников

- `googleSheets` и `debt` были включены. Имеющийся JSON сервисного аккаунта Google проверен запросами только метаданных: доступ к обеим сохранённым таблицам есть (33 и 26 листов). Его можно использовать повторно. Это проверка доступа, а не подтверждение полноты расчётных данных за все периоды.
- `fintablo` был включён. Необходимо снова указать действующий API-токен, проверить доступ и выполнить синхронизацию.
- `crm` была выключена. Перенос сохраняет её выключенной; реквизиты потребуются только при решении её использовать.

Дополнительный путь сохранения: рабочий Vercel всё ещё имеет исходный ключ внутри runtime. Для доступных архивов дашборда существующий GET `/api/dashboard?start=YYYY-MM-DD&end=YYYY-MM-DD&archiveOnly=1` (без `maintenance=1`) может вернуть расшифрованный отчёт без обновления источников или записи архива. Код проверен: при отсутствии подходящего готового архива запрос возвращает 204 до захвата write lease. В копии 26 архивов dashboard и один opiu. Этот путь требует действующей авторизованной сессии; проверка браузера вернула «Требуется вход», поэтому расшифрованные отчёты пока не выгружены. У ОПиУ такого гарантированного read-only режима в опубликованном API нет; обычный `/api/opiu` может запускать фоновую проверку и для этой задачи не вызывается. Экспорт готового отчёта не равен восстановлению всех исходных снимков и не означает автоматическое включение старого кэша в новую базу.

Архивы можно заново построить только за периоды, для которых исходные Google-таблицы / API ещё содержат полные данные. Новая выгрузка не восстанавливает точное прежнее состояние отчёта на дату старого сохранения. Старые Excel и отдельный `mart-data.json` могут служить дополнительными материалами для сверки, но не автоматически заменяют все 27 архивов. Если исходный ключ найдётся позже, полная зашифрованная копия сохранена для отдельного восстановления.

## Отдельное хранилище

На текущий момент отдельной базы нет. Код использует Neon HTTP driver `@neondatabase/serverless`: произвольный PostgreSQL Timeweb без совместимого HTTP endpoint не является готовой заменой. Для текущего варианта нужна отдельная пустая база Neon. Альтернатива с обычным PostgreSQL потребует отдельного изменения драйвера и проверки.

Нельзя применять восстановление или новый ключ к production-базе Vercel. Для будущего нового хранилища подготовлен отдельный защищённый локальный файл с сохранёнными пятью настройками Timeweb и новым независимым ключом; `DATABASE_URL` в нём пустой. Этот файл не включён в Git. Не запускайте `setup-auth`: он изменит действующий доступ.

## Инструменты

Все команды запускаются на доверенной локальной машине, из корня проверенного checkout, после `npm ci`. Аргументы — пути к приватным JSON-файлам; значения секретов не передаются в командной строке. Для новых выгрузок выбирайте новые имена: существующие копии не перезаписываются.

```sh
# Только чтение source DATABASE_URL. Ключ расшифрования не требуется.
npm run recovery:export -- /private/path/source-env.json private-data/source-backup.json private-data/inventory.json

# Проверка backup и конфликтов пользователей, без сетевых обращений и записи в базу.
npm run recovery:plan -- /private/path/target-env.json private-data/source-backup.json

# Только после указания URL отдельной пустой базы в target-env.json.
# В том же файле оператор должен явно установить
# RECOVERY_CONFIRM_EMPTY_TARGET="new-isolated-timeweb-storage".
npm run recovery:import -- /private/path/target-env.json private-data/source-backup.json
```

Импорт блокирует совпадающий endpoint/имя базы, включая pooler-алиас. Первая операция внутри одной Serializable-транзакции также отказывает при наличии любой таблицы в схеме public. Все восемь миграций и восстановленные настройки применяются атомарно: ошибка откатывает всю транзакцию. Программа не умеет очищать старую базу и не перезаписывает существующие таблицы. Не передавайте исходный DATABASE_URL как целевой даже с другим логином.

После импорта:

1. Проверить сохранение реестра и доступов. Для `migration:check` использовать только target-env.json.
2. В тестовом окружении с новой базой заново указать реквизиты двух Google-подключений и Финтабло. Проверить каждый источник, включить и синхронизировать его.
3. Сверить основные расчёты с Vercel и построить доступные архивы; проверить Excel, вход, сохранение сессии и ограничения пользователей в браузере.
4. Только затем перенести настройки новой базы в Timeweb, сохранив пять текущих переменных авторизации и точный APP_ORIGIN из `TIMEWEB-DEPLOY.md`.
5. Обновить подключённую `restore/timeweb-demo-clean`, проверить успешный деплой, commit в панели и `/build-info.json`.

Откат: ветка `rollback/timeweb-before-vercel-20261110` на `cc902f8111685d4ac9c56ca4ebd45452c504447f`, предыдущий успешный деплой Timeweb и защищённый экспорт прежних настроек. Ветка, подключённая к Timeweb, до готовности нового хранилища не обновляется.
