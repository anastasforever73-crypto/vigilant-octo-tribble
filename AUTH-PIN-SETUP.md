# Авторизация «Март-Трейд»: настройка PIN

## Причина сообщения

`app/api/auth/login/route.ts` возвращает HTTP 503 и сообщение «Вход ещё не настроен. Обратитесь к владельцу дашборда.», если `authConfigured()` возвращает false.
До исправления требовались одновременно AUTH_SECRET длиной не менее 32 символов, два разных логина USER_LOGIN/ADMIN_LOGIN и два корректных scrypt-хеша USER_PASSWORD_HASH/ADMIN_PASSWORD_HASH.
Проверка `vercel env ls production` 21 сентября 2026 года показала, что все пять переменных отсутствуют в существующем production-проекте. Наличие локального `.env.local` не настраивает окружение Vercel.

## Новое поведение

- Достаточно настроенного администратора и секрета сессии; обычные пользователи необязательны.
- PIN — строка из ровно четырёх цифр ASCII; начальные нули сохраняются. Проверка одинакова в форме, API и CLI.
- PIN хранится только в виде scrypt-хеша с индивидуальной случайной солью. Открытый PIN не записывается в исходники, файлы окружения или логи.
- Старая пара USER_LOGIN/USER_PASSWORD_HASH продолжает работать; дополнительные пользователи задаются через DASHBOARD_USERS_JSON. Все они имеют роль user.
- Логины регистрозависимы, уникальны, без пробелов по краям, длиной до 200 символов. До 100 дополнительных пользователей. Ошибочный JSON, хеш, дубликаты или попытка назначить роль admin через список пользователей блокируют вход.
- HttpOnly/Secure/SameSite=Strict cookie действует 8 часов. Подпись связывает сессию с ролью, логином и текущим хешем. Удаление пользователя/смена хеша инвалидирует его сессии; обновление формата требует повторного входа для прежних сессий.
- Выход очищает cookie; без неё proxy и API отклоняют доступ. Как и прежде, серверного списка отозванных cookie нет: заранее скопированный токен действует до истечения срока или смены учётных данных.
- Сохранены проверка Origin и блокировка после пяти ошибок на 15 минут. Счётчик, как и ранее, находится в памяти экземпляра сервера; единого лимита между экземплярами Vercel нет.

## Переменные Vercel

| Имя | Значение |
| --- | --- |
| AUTH_SECRET | Случайный секрет подписи длиной не менее 32 символов |
| ADMIN_LOGIN | Выбранный владельцем логин администратора |
| ADMIN_PASSWORD_HASH | Scrypt-хеш выбранного четырёхзначного PIN |
| DASHBOARD_USERS_JSON | Необязательный JSON-массив объектов с полями login и passwordHash; без пользователей — пустой массив |
| USER_LOGIN, USER_PASSWORD_HASH | Необязательная совместимая пара для одного обычного пользователя; задавать обе либо ни одной |

Безопасная схема списка приведена в `.env.example`. PIN, ADMIN_PIN и открытые пароли в JSON не используются. Не добавляйте префикс NEXT_PUBLIC_.

## Подготовка значений без записи PIN

В интерактивном терминале проекта выполните:

```bash
node scripts/hash-password.mjs
```

Введите желаемый четырёхзначный PIN и повторите его. Ввод не отображается. Команда выводит только строку хеша для ADMIN_PASSWORD_HASH. Для каждого пользователя повторите команду и поместите хеш в поле passwordHash соответствующего объекта JSON. Не передавайте PIN аргументом команды.

Для нового AUTH_SECRET выполните локально:

```bash
node -e "process.stdout.write(require('node:crypto').randomBytes(48).toString('hex'))"
```

Скопируйте результат в Vercel. Не публикуйте его. Если AUTH_SECRET уже настроен, сохраняйте его, если не требуется завершить все сессии.

## Добавление в существующий production-проект

1. Откройте https://vercel.com/anastasforever73-2206s-projects/vigilant-octo-tribble/settings/environment-variables.
2. Нажмите Add Environment Variable. Выберите окружение Production.
3. Добавьте AUTH_SECRET, ADMIN_LOGIN и ADMIN_PASSWORD_HASH. Для секретов включите Sensitive. Значение хеша вставляйте буквально, без внешних кавычек и без экранирования знаков `$`.
4. При необходимости добавьте DASHBOARD_USERS_JSON со списком выбранных логинов и хешей. Это строка JSON; целиком без внешних кавычек. Также отметьте Sensitive. Не дублируйте ADMIN_LOGIN или USER_LOGIN в этом списке.
5. Сохраните. Остальные переменные, источники данных и ключ шифрования подключений не меняйте. Не запускайте `setup-auth --reset` для настройки Vercel: этот старый помощник меняет только локальный файл.
6. Изменения переменных применяются к новой публикации. Сначала опубликуйте исправленный код из текущего рабочего каталога:

```bash
npx tsc --noEmit
npm run build
VERCEL_PROJECT_ID=prj_98zd9X8qLCsJQjYNoWsUVMEpUIF0 VERCEL_ORG_ID=team_ExQghDiDAC8yDuClYjncyfDV npx vercel --prod
```

Идентификаторы берутся из существующей `.vercel/repo.json` и предотвращают создание другого проекта. Если CLI запросит авторизацию, выполните `npx vercel login`, затем повторите публикацию. Дождитесь READY.

7. Откройте https://vigilant-octo-tribble-eosin.vercel.app/login. Проверьте вход администратора, выход, отказ с неверным PIN и вход каждого пользователя; у обычного пользователя нет доступа к настройкам источников.

Настройка реальных production-секретов и проверка настоящего аккаунта требуют PIN, выбранного владельцем. Тесты используют только одноразовые случайные данные и не заменяют эту проверку.
